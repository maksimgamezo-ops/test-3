# Продолжение по поручению пользователя

Пользователь просит законченный работающий сайт, кнопки, анимацию и эффекты. Сохраняется утверждённый дизайн и inline-исполнение; повторное согласование того же решения не нужно.

1. Регрессии на все действия viewer: видимый выбранный ракурс, повтор, клавиатурный поворот/масштаб, сброс, ошибка→повторная загрузка; исходный запуск должен показать отсутствующие действия.
2. Чистый модуль положений камеры и тесты границ. Плавная постановочная камера, передача управления после финала, явные пользовательские кнопки управления.
3. Реальные эффекты главы/освещения, адаптивная сцена, состояния загрузки и восстановления. Reduced-motion остаётся статичным и доступным.
4. Переходы при прокрутке и навигация по пяти главам с реальными якорями; никакого scroll-jacking и зависимости текста от JS.
5. Полная production-проверка существующих и новых сценариев, визуальная проверка desktop/mobile, независимый review и исправления. Доступный извне адрес зависит от сервиса размещения; вопрос задан параллельно работе. Сохранённый выбор репозиториев не менять.

Решение после ответа пользователя «хостинга пока нет»: собрать автономный HTML из тех же React-компонентов, всех страниц, локальных шрифтов и реального GLB. В автономной копии маршруты переключаются через hash и не требуют сервера. Production-версия сохраняет обычные Next.js маршруты, SSR и SEO. Для скачиваемой копии нужны только браузер и JavaScript; внешние загрузки не допускаются. Добавлены два browser-теста с полностью отключённой сетью.

Проверки выявили нагрузку от transmission-материалов при непрерывных переходах камеры. Добавлен профиль для мобильного/программного рендера: та же геометрия и управление, облегчённое остекление и отключённые динамические тени; полные материалы остаются на подходящих desktop GPU. Подмена модели не выполняется.

Управляемый Chromium запрещает file:// политикой администратора. Политика не менялась. Автономный HTML проверяется через загрузку его полного содержимого в разрешённый браузерный документ с context.offline=true. Это проверка реального итогового HTML и его встроенных ресурсов, но не разрешения file:// на пользовательском компьютере; ограничение нужно явно указать в документации.

Измеренная диагностика в текущем SwiftShader: до оптимизации готовность 2234 ms, переход к итогу 10307 ms от старта, приближение 18289 ms от старта; после оптимизации готовность 1899 ms, переход к итогу 8830 ms, приближение 8879 ms. Это единичная диагностическая последовательность, не обещание времени отклика на всех устройствах. После прокрутки к началу Canvas теперь штатно размонтируется. Для слабого GPU разрешение ограничено DPR .75 и ракурс меняется мгновенно; на подходящем GPU сохраняются плавные переходы и полные материалы.

Независимый read-only review продолжения выявил три важных замечания: offline-skip-link не переносил фокус; наблюдение за всей секцией сохраняло Canvas при чтении деталей; полный текст лицензий библиотек не попадал в HTML. Регрессии воспроизведены до исправления. Исправления: фокус на целевом элементе с временным tabindex, отдельная область viewer+controls без описания/главы деталей, сбор полных notices по esbuild-metafile для всех реально включённых пакетов. Отсутствующий в npm Fiber LICENSE взят из официального v9.8.2 tag с сохранённой TLS-проверкой и provenance. Добавлена визуальная проверка canvas до/после команды поворота: подпись сама по себе больше не считается достаточной проверкой камеры.
