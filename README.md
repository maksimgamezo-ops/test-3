# BAUPLANINVEST

Русскоязычный сайт девелопера коммерческой недвижимости. Next.js App Router, TypeScript, React Three Fiber и оригинальная модель Blender. Проекты компании не выдумываются: здание обозначено как демонстрационный концепт.

## Запуск

Нужен Node.js 24 и npm 11. Зависимости зафиксированы в `package-lock.json`.

```sh
npm ci
npm run dev
```

В `next.config.ts` явно разрешён локальный dev-origin `127.0.0.1`: это необходимо для HMR при запуске с hostname `0.0.0.0`. Произвольные внешние origin не разрешены. Браузерные функциональные проверки выполняются на production-сборке:

```sh
npm run build
npm start
```

По умолчанию порт 3000; другой: `npm start -- --port 3001`. Живой сервер необходимо запускать заново после восстановления облачной среды. Используйте существующий изолированный checkout; дополнительный Git worktree не нужен.

## Проверки

```sh
npm test
npm run typecheck
npm run build
npm run test:e2e
```

Playwright проверяет production-сборку и при необходимости сам запускает `npm start -- --port 3001`. Сначала выполните build. Chromium: автоматически используется `/usr/bin/chromium`, если он установлен; иначе `npx playwright install chromium`. Можно задать `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` и `TEST_PORT`. Доступ к CDN Playwright может требовать изменения сетевых настроек среды; проверка не обходит ограничения. Для строгой проверки свежего процесса запускайте `CI=1 npm run test:e2e` при свободном порте. Результаты и непроверенные платформы — [docs/qa.md](docs/qa.md).

## Что и где редактировать

- `content/company.ts`: оба телефона, email, реквизиты, навигация, предлагаемые этапы. Все контакты и Organization JSON-LD берутся отсюда.
- `app/page.tsx`: пять глав главной. Тексты внутренних страниц — `app/<route>/page.tsx`.
- `app/globals.css`: токены, адаптивность и состояния интерфейса.
- `lib/sequence.ts`: детерминированная 15-секундная последовательность; `components/architecture/`: сцена, управление, резервный режим.
- `scripts/create_architecture.py`: исходник авторской геометрии. `assets/architecture.blend`: редактируемый Blender-проект. Происхождение материалов — [docs/assets.md](docs/assets.md).

## Архитектура и анимация

Воспроизведение запускается посетителем: участок 0–3 с, перекрытия 3–6 с, структура и фасад 6–10 с, детали и окружение 10–13 с, итог 13–15 с. Модель разделена на шесть объединённых групп для ограничения числа draw calls. Последовательное отсечение по высоте раскрывает геометрию; перемотка не зависит от истории воспроизведения. После финала доступно ограниченное вращение и сброс камеры. Сцена не загружается до действия посетителя; DPR ограничен 1.5, рендер выполняется по требованию, за пределами видимости Canvas размонтируется. Уменьшенное движение показывает статичный рендер. Ошибка WebGL/загрузки не блокирует содержимое.

Перегенерация ассетов (Blender 4.3+, Python с Pillow для WebP):

```sh
blender -b -t 5 -P scripts/create_architecture.py
python scripts/convert_posters.py
```

Это отдельная операция подготовки ассетов, не часть npm ci/build. Cycles CPU, 192 samples, без недоступного в данной сборке OIDN. Рендер может занять несколько минут на изображение. Никакие внешние текстуры и закрытые ключи не нужны. Существующие кадры лампы в `large/` не используются и не изменялись.

## Размещение

Подходит Node.js-хостинг с поддержкой Next.js 16 (или соответствующая платформа Next.js). Сборка не требует ключей. Задайте реальный `SITE_URL` в окружении **сборки**, например утверждённый HTTPS origin без пути; затем пересоберите и перезапустите. Пример имени переменной — `.env.example`. До настройки домена страницы получают `noindex`, robots запрещает индексацию, sitemap пуст и canonical отсутствует. Next.js может выводить предупреждение об отсутствующем metadataBase; это ожидаемо до выбора реального домена, а не основание подставлять выдуманный адрес.

```sh
npm ci
npm run build
npm start -- --port 3000
```

Публичный HTTPS и сертификат настраиваются средствами хостинга/reverse proxy. Проксируйте все маршруты и `/_next/`, передавайте исходные Host и X-Forwarded-Proto, включите сжатие и корректное кеширование статических ассетов. Реквизиты, тексты и юридический черновик должны быть утверждены до публикации. Не публикуйте `.env` и резервные копии. Security headers задаются в `next.config.ts`; HSTS включается на хостинге после проверки HTTPS всех нужных поддоменов. Формы, обработчика лидов и аналитики сейчас нет; rate limiting для формы добавляется вместе с реальной интеграцией, а ограничение запросов к сайту — на хостинге.

Для резервного копирования сохраняйте исходники, lockfile, `assets/`, `public/` и отдельно безопасную конфигурацию размещения; `.next` и node_modules воспроизводимы. После восстановления: npm ci → build → smoke/e2e → переключение трафика. Проверяйте восстановление и предыдущую рабочую версию перед обновлениями. Живые процессы из snapshot не восстанавливаются.
